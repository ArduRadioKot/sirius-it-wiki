## Возможности

| | |
|---|---|
| **Учёба** | Конспекты по дням и предметам, формулы LaTeX, SVG-схемы, PDF для скачивания |
| **Самопроверка** | 130+ вопросов с разбором каждого ответа, сгруппированных по темам |
| **Расписание** | Четыре группы `ИОП-ИТ`, отсчёт до пары, аудитории, преподаватели, подсветка текущей пары |
| **Напоминания** | Уведомления за 5–30 минут и подписка на календарь: Google, Apple, Notion, ICS |
| **Жизнь в кампусе** | Общежитие, транспорт, сервисы, мероприятия, тайм-менеджмент |
| **PWA** | Устанавливается как приложение и работает офлайн; системная / светлая / тёмная тема |

## Быстрый старт

```bash
git clone https://github.com/ArduRadioKot/sirius-it-wiki.git
cd sirius-it-wiki
python3 scripts/serve.py 8765
```

Откройте http://localhost:8765. Локальный сервер отключает кэш и service worker и проксирует расписание университета через `/__schedule`, поэтому правки видны сразу.

## Как писать статьи

Создайте `.md` в `life/` или в папке даты внутри `articles/` (если дата не подтверждена — `articles/undated/`) и сделайте push в `main`. Workflow [`content-index.yml`](.github/workflows/content-index.yml) сам пересоберёт `content-index.json`; `node generate-index.mjs` нужен только для локального просмотра.

### Шапка статьи

```md
---
title: Центральная симметрия
description: Короткое описание для списков
subject: Линейная алгебра
order: 1
---
```

`subject` — для режима **«По предметам»** (без него статья попадёт в **«Другое»**); дата папки — для **«По дням»**; `order` задаёт порядок статей внутри дня.

### Формулы

KaTeX: `$...$` — внутри строки, `$$...$$` — отдельной формулой по центру.

```md
Площадь круга: $A = \pi r^2$.

$$
e^{i\pi} + 1 = 0
$$
```

### Схемы

SVG кладутся в `assets/diagrams/`, путь — от корня проекта:

```md
![Треугольник и два его образа](assets/diagrams/motion-orientation.svg)
```

### Файлы для скачивания

```md
:::download
title: Скачать рукописный конспект
file: articles/files/linal1.pdf
description: Конспект лекций по линейной алгебре.
:::
```

Путь в `file` — от корня проекта; `title` и `description` необязательны.

### Квизы

Вопрос с одним правильным ответом; `answer` — номер верного варианта, начиная с единицы. Все квизы также попадают на страницу **«Самопроверка»**.

```md
:::quiz
question: Чему равно $(g\circ f)(x)$?
option: $f(g(x))$
option: $g(f(x))$
answer: 2
explanation: Сначала действует $f$, затем $g$.
:::
```

## Расписание

Страница **«Расписание»** показывает `ИОП-ИТ-26/1`, `ИОП-ИТ-26/2`, `ИОП-ИТ-25/1` и `ИОП-ИТ-25/2`: выбор группы и дня, полоса недели с числом пар, отсчёт до следующей пары, аудитории и преподаватели. Время всегда московское.

### Как обновляется расписание

```text
GitHub Actions (каждые 30 мин) ──► Yandex Cloud Function ──► schedule.siriusuniversity.ru
          │                               (российский IP)
          └─► data/schedule.json + data/calendars/*.ics ──► GitHub Pages
```

- [`schedule.yml`](.github/workflows/schedule.yml) запускает `scripts/publish-schedule.sh` в :17 и :47 каждого часа и вручную через *Run workflow*. Коммит появляется, только если поменялись пары или снимку больше ~2 часов.
- Сайт университета отвечает только российским IP, поэтому workflow просит `cloud/yandex-function` (бесплатная квота) собрать текущую и две следующие недели. Развернуть один раз: `bash cloud/yandex-function/deploy.sh` (нужны `yc` и `gh`) — скрипт сохранит секреты `SCHEDULE_COLLECTOR_URL` и `SCHEDULE_COLLECTOR_TOKEN`.
- При ошибке или неожиданном формате остаётся предыдущий снимок, коммита нет. Одновременные занятия подгрупп сохраняются отдельно.
- Секрет `SCHEDULE_PROXY_URL` (HTTP(S)-прокси, `http://USER:PASSWORD@HOST:PORT`) — запасной вариант для прямой загрузки. Пароль не храните в файлах репозитория.
- GitHub может задерживать запуски по расписанию и приостанавливает их после 60 дней без активности в репозитории.

Приложение загружает опубликованный снимок при открытии, возврате во вкладку и появлении сети. На GitHub Pages оно не обращается к сайту университета напрямую (это всегда блокирует CORS). Локальный `scripts/serve.py` умеет собирать расписание вживую через `/__schedule`.

### Напоминания и календари

- **Напоминания** — за 5, 10, 15 или 30 минут до пары выбранной группы. Разрешение запрашивается только по кнопке, тестовое уведомление подтверждает, что всё работает. Таймеры работают, пока приложение открыто или недавно свёрнуто (push-сервера нет); снимок старше суток не уведомляет. На iPhone — только в приложении с экрана «Домой».
- **Google / Notion** — на компьютере открывают Google Календарь с лентой группы; на телефоне копируют ссылку и объясняют, как добавить её на calendar.google.com. Notion Calendar показывает тот же Google-календарь.
- **Apple** — системное окно подписки `webcal://` на iPhone, iPad и Mac.
- **Ссылка** копирует адрес ленты; **ICS** скачивает разовый файл (подписка обновляется, файл — нет).

Чтобы получать напоминания при закрытом приложении, подпишитесь на календарь.

## Офлайн и установка

**«Установить приложение»** вызывает установку PWA или показывает подсказку (нужен HTTPS; localhost подходит). После первого открытия и статуса «готово офлайн» без сети работают оболочка, тексты статей с формулами и последнее расписание (около 2 МБ). PDF, внешние картинки и ссылки не кэшируются. **«Обновить»** загружает свежее расписание, очищает старый кэш и перезапускает приложение; на iPhone иногда нужно закрыть и снова открыть его.

Кнопка темы переключает **система → светлая → тёмная**, выбор сохраняется локально.
