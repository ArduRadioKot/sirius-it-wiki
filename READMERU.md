# Sirius Wiki

[English README](README.md)

Статическая студенческая вики на HTML, CSS и JavaScript. Публикуется на GitHub Pages.

## Структура

```text
sirius-it-wiki/
├─ life/                  # статьи про жизнь в университете
├─ articles/
│  ├─ YYYY-MM-DD/         # учебные материалы по дням
│  ├─ undated/            # материалы без подтверждённой даты
│  └─ files/              # PDF и другие файлы для скачивания
├─ data/schedule.json     # снимок расписания
├─ data/calendars/        # ICS для Google и Notion
└─ vendor/katex/          # офлайн-рендер формул
```

`life/` — постоянные статьи про жизнь в университете.

`articles/YYYY-MM-DD/` — учебные статьи по дням. Если дата ещё не подтверждена, используй `articles/undated/`.

## Как добавить статью

Создай `.md` файл в `life/` или в папке нужного дня внутри `articles/` и отправь изменения в GitHub.

В начале файла можно указать:

```md
---
title: Название статьи
description: Короткое описание
subject: История
order: 1
---
```

Поле `subject` используется для режима **«По предметам»** в разделе «Учёба». Если его не указать, статья попадёт в **«Другое»**. Дата папки по-прежнему нужна для режима **«По дням»**.

## Формулы LaTeX

Статьи поддерживают формулы LaTeX через KaTeX. Внутри строки — одиночные `$...$`:

```md
Площадь круга: $A = \pi r^2$.
```

Отдельная формула по центру — двойные `$$...$$`:

```md
$$
e^{i\pi} + 1 = 0
$$
```

## Скачивание файлов

Блок для скачивания в статье:

```md
:::download
title: Скачать рукописный конспект
file: articles/files/linal1.pdf
description: Конспект лекций по линейной алгебре.
:::
```

Путь в `file` — от корня проекта. `title` и `description` необязательны.

## Тема, расписание и установка

Кнопка темы в правом верхнем углу шапки переключает **система → светлая → тёмная** (иконки монитора / солнца / луны). Выбор сохраняется локально. В тёмной теме — чёрная подложка.

Страница **«Расписание»** — компактное расписание для `ИОП-ИТ-26/1`, `ИОП-ИТ-26/2`, `ИОП-ИТ-25/1` и `ИОП-ИТ-25/2`: группа и день, отсчёт до пары, аудитории, преподаватели и подсветка текущей пары. Время всегда московское. Длинные пояснения со страницы убраны; статус — короткая строка внизу.

Кнопка **«Установить приложение»** вызывает установку PWA или показывает краткую инструкцию. Нужен HTTPS (для разработки подходит localhost). После первого успешного открытия и статуса готовности офлайн доступны оболочка, тексты статей с формулами и последний снимок расписания. Примерный объём — около 2 МБ. PDF, внешние картинки и ссылки сами не кэшируются. Браузер может очистить данные при нехватке места. Кнопка **«Обновить»** заново загружает опубликованное расписание, очищает старый кэш и перезапускает приложение. На iPhone в Safari после этого иногда нужно закрыть приложение и открыть снова.

### Автоматическое расписание

`python3 scripts/update-schedule.py` читает публичный Livewire-интерфейс
https://schedule.siriusuniversity.ru. Сохраняются текущая и две следующие недели.
При ошибке или неожиданном формате предыдущий `data/schedule.json` не перезаписывается.
Одновременные занятия подгрупп сохраняются отдельно. Названия и аудитории берутся из источника.

Workflow `.github/workflows/schedule.yml` обновляет снимок каждые 2 часа (и вручную через *Run workflow*) скриптом `scripts/publish-schedule.sh`. Коммит в `main` появляется, только если поменялись пары или снимку больше 12 часов, после чего GitHub Pages пересобирается. Сайт университета отвечает только российским IP, поэтому серверы GitHub напрямую до него не достают: workflow просит маленькую Yandex Cloud Function (`cloud/yandex-function`, бесплатная квота) собрать расписание и вернуть JSON. Развернуть её один раз: `bash cloud/yandex-function/deploy.sh` (нужны CLI `yc` и `gh`) — скрипт сам сохранит секреты `SCHEDULE_COLLECTOR_URL` и `SCHEDULE_COLLECTOR_TOKEN` в репозитории. Если сборщик не ответил, запуск оставляет старый снимок и ничего не коммитит. Запуски по расписанию могут опаздывать, а после 60 дней без активности в репозитории GitHub их приостанавливает.

Приложение при заходе и раз в 4 часа сначала пробует собрать расписание с сайта университета **на устройстве пользователя**, затем берёт опубликованный снимок. Браузер на GitHub Pages обычно не может прочитать ответ университета (CORS и SameSite-cookies), тогда остаётся снимок с Pages. Живой сбор через `/__schedule` есть у локального `python3 scripts/serve.py 8765`. При сбое загрузчик в Actions делает три попытки с новой сессией; если источник недоступен, сохраняется последняя корректная версия с исходной датой обновления. Кнопка обновления без ожидания интервала повторяет ту же схему.

Если общая копия неполная или сервер GitHub не может достучаться до расписания, в workflow можно задать секрет `SCHEDULE_PROXY_URL` (HTTPS-прокси). На сайт всё равно попадает последний полный снимок из репозитория. **Офлайн** остаётся уже сохранённая копия.

### Напоминания

Можно выбрать 5, 10, 15 или 30 минут до начала. Разрешение браузера запрашивается по кнопке. Уведомления относятся к выбранной группе; одновременные занятия объединяются. Снимок старше суток не вызывает уведомлений. Таймер работает только пока приложение открыто; в фоне браузер может его приостановить. Сервер Push не подключён.

**Google** и **Notion** одним нажатием открывают Google Календарь с лентой группы — остаётся подтвердить добавление. Notion Calendar сам не подписывается на ICS, поэтому тот же Google-календарь появится там, если подключён этот Google-аккаунт. **ICS** скачивает файл для Apple Календаря и других приложений. Файл после смены расписания нужно импортировать снова; подписка обновляется примерно раз в 4 часа. На iPhone веб-уведомления могут требовать установки на экран Домой.

### Проверка

```sh
node --test tests/*.test.cjs
python3 -m unittest discover -s tests
node scripts/version-worker.mjs
python3 scripts/serve.py 8765
```

Скрипт версионирования создаёт новый ключ офлайн-кэша при изменениях оболочки или ресурсов. KaTeX 0.16.22 хранится в `vendor/katex` с лицензией MIT для работы формул без CDN.


### Если сайт доступен в браузере, но не загрузчику

Успешная публикация Pages не означает успешную загрузку расписания: при тайм-ауте
сохраняется последняя версия. Проверьте дату данных и шаг `Fetch university schedule`
в GitHub Actions. Ошибка согласования TLS возникает до парсинга HTML; сама по себе
она не доказывает блокировку по стране IP.

Загрузчик поддерживает доверенный HTTP(S)-прокси, через который доступен сайт.
В настройках репозитория **Settings → Secrets and variables → Actions** создайте
секрет `SCHEDULE_PROXY_URL` с адресом прокси в формате
`http://USER:PASSWORD@HOST:PORT` (специальные символы логина и пароля кодируются для URL).
Пароль не добавляйте в файлы репозитория. Без секрета остаётся обычное прямое
подключение в GitHub Actions. Прокси применяется только к шагу получения расписания;
проверка сертификата сайта остаётся включённой. SOCKS-прокси этим загрузчиком не поддерживаются.
После настройки запустите workflow вручную и проверьте появление четырёх групп в JSON
и свежую дату обновления. Далее действует интервал 4 часа.

Альтернатива — запускать загрузчик на своём российском сервере или постоянно работающем
компьютере с доступом к сайту и публиковать полученный `data/schedule.json` в репозиторий.
Адрес прокси или такой сервер проект сам не предоставляет; до их настройки маршрут
загрузки не меняется.
